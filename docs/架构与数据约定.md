# 影游剪辑台：架构与数据约定

给改代码的人看：程序分几块、各自管什么，读写哪些文件，调用哪些外部脚本，改的时候要注意什么。怎么用见 [设计与使用](影游剪辑台_设计与使用.md)。

2026-11-08 按 v0.6 的代码整理。

## 总体结构

```
┌──────────── Electron 主进程（Node） ────────────┐      ┌──────── 渲染进程（浏览器） ────────┐
│ main.js     窗口、菜单、IPC 入口、跑 Python 任务  │◀────▶│ preload.js  只把白名单 API 暴露成 S │
│ core.js     读写游戏 index.html 和各种 json      │ IPC  │ renderer/   整个界面（无框架，原生 JS）│
│ voice-*.js  声音参考登记、复刻 / 试听            │      └──────────────────────────────────┘
└───────┬─────────────────────────────────────────┘
        │ spawn（python -u 脚本 参数…，日志实时转发到界面任务栏）
        ▼
 storyboard\*.py   出图、质检、修图、参考图、衔接检查、手绘构图
 autofix\*.py      视频提示词、时长、草稿、生成 + 质检 + 自动重拍、手绘动作
   └ 调用 qc\*.py（视频 / 声音质检）、motion_ref\*.py（参考视频、2.5D 预演）
 voice_clone_worker.py   MiniMax 声音复刻 / 试听（从 stdin 读一个任务，回一行 JSON）
```

仓库的目录：

```
OptMe\                    = 影游剪辑台\resources\app\
├─ main.js  preload.js  core.js  voice-*.js  voice_clone_worker.py   主进程
├─ renderer\              界面
├─ storyboard\  autofix\  qc\  motion_ref\   Python 工具（拷到项目根目录用，见「Python 工具」）
├─ requirements.txt       Python 依赖
├─ docs\                  文档
├─ skills\yingyou-flow\   给 Claude / Codex 的流程 skill
└─ backup_*\              本机的修改前备份，不进仓库（.git\info\exclude）
```

- 主进程只做文件读写和起子进程；所有界面逻辑都在渲染进程。
- 渲染进程拿不到 Node，只能用 `preload.js` 暴露的 `S.*`（`S.load`、`S.save`、`S.replace`、`S.runTool`……）。加新的主进程能力时，`main.js` 的 `ipcMain.handle` 和 `preload.js` 两边都要加。
- 花钱、调用外部 AI 的事都在 Python 里，剪辑台只负责传参数、显示日志、任务结束后刷新数据。

## 代码文件

| 文件 | 管什么 |
|---|---|
| `main.js` | 窗口和菜单；`ipcMain.handle` 把 IPC 转给 `core.js`；`tool:run` 起 Python 任务（脚本白名单、最多同时 4 个、找 Python 的顺序） |
| `preload.js` | `contextBridge` 暴露 `S` 对象，界面只能调用这里列出的方法 |
| `core.js` | 解析和写回 `index.html` 里的剧本数据；素材替换和备份；分镜表、参考图、审阅记录、视频分镜表的读写；导出游戏包（自己写 zip） |
| `voice-refs-store.js` | 声音参考登记表 `refs\voice_refs.json` 的读写、导入录音、校验路径和编号 |
| `voice-clone-service.js` | 声音复刻 / 试听 / 单句配音的状态机：防重复提交、「待核实」状态、生成期间录音被换的检查 |
| `voice_clone_worker.py` | 实际调用 MiniMax 接口；不自动重试，不打印密钥 |
| `renderer/index.html`、`style.css` | 界面骨架和样式 |
| `renderer/app.js` | 主体（约 3500 行）：项目加载、时间线、故事板、属性面板、审阅框架和 ⓪～④ 页、框选修图、提示词自动检查 `lintShot`、剧本检查 `sceneChecks`、视频模型价格 `ENGINES` |
| `renderer/review-flow.js` | ①～⑤ 页之间的跨页定位（停在同一个镜头 / 台词上）和翻页记忆 |
| `renderer/script-video.js` | 剧本卡片里的视频播放、跳到成片、右键写审阅意见 |
| `renderer/dialogue.js` | ⑤ 台词页：配音状态、按角色筛选、用复刻音色生成单句配音、台词审阅意见 |
| `renderer/voice-refs.js` | ⓪ 参考页的「声音音色」：登记、选录音、复刻、试听 |
| `renderer/audio-library.js` | 项目音频选择器：分离音频优先、多段录音在本地合并成 WAV |
| `renderer/asset-sync.js` | 审阅页的素材刷新（文件、视频分镜表、分镜表一起重读）；首帧换了时同步视频；台词 / 原声静音；时间线审阅意见 |
| `renderer/final-load.js` | ④ 成片页的视频按需加载，同时只保留一个在播 |
| `renderer/local-video.js` | ④ 成片页的本地视频替换和本地候选 |
| `renderer/*.css` | 各模块自己的样式，文件名和 js 对应 |

renderer 下的 js 都是普通 `<script>`，共用全局变量（`P` 当前项目、`RV` 审阅页状态、`S` 主进程 API、`cur` 当前场景）。加载顺序由 `index.html` 决定，新文件要加进去。

## 剧本数据（index.html）

剧本直接存在游戏的 `index.html` 里，`core.js` 按固定的开头字符串找到每一段、解析、改完再原样写回：

| 变量 | 写法 | 内容 |
|---|---|---|
| `N` | `const N={…}` | 场景表。每场有 `lines`（台词）、`choices`（选项，可带 `if` 需要的线索）、`lock`（密码锁，`ok` / `fail` 去哪）、`gain`（给出的线索）、`end`（结局） |
| 台词 | `["说话人","台词",{…}]` | 第三项可选：`img`（分镜图，如 `"l/ride_00"`）、`mute`（这句静音）、`vo_bind`。说话人以 `@` 开头的是特殊行：`@shot` 插入镜头、`@cap` 字幕卡 |
| `VOT` | `const VOT=/*VO_MAP*/{…}` | 台词文字 → 配音文件名（`vo/<值>.mp3`）。相同台词共用一个配音 |
| `SHOTS` | `const SHOTS=new Set(/*SHOTS*/[…])` | 插入镜头 |
| `LIMG` | `const LIMG=new Set(/*LIMG*/[…])` | 逐句分镜图登记（兼容旧写法） |
| `TRIM` | `const TRIM=/*TRIM*/{…}` | 视频剪辑入点 / 出点 |
| `VAUD` | `const VAUD=/*VAUD*/{…}` | 视频原声：音量、静音、分离出的文件 |
| `BGM`、`AMB`、`SHOT_SFX` | `const BGM={…}` 等 | 音乐、环境声、镜头音效 |
| `CLUES` | 线索本 | 线索 id → 文字 |
| `ACTS` | `const ACTS=[…]` | 分幕（素材库「场景」页按它分组） |

**改游戏模板时要注意**：上面这些开头字符串（包括 `/*VO_MAP*/` 这类注释标记）是剪辑台找数据的唯一依据，改了剪辑台就读不到。

### 静音（2026-11-08 修过）
两种静音都要游戏代码配合：
- 台词静音：台词第三项 `mute: true`，游戏播配音时要读 `line[2]?.mute`；
- 视频原声静音：`VAUD["vid/x.mp4"].muted = true`，游戏播原声时要读 `a.muted`。

现在的 `moban_game\index.html` 已经自带这两处。剪辑台的处理（`core.js` 的 `muteSupport` / `upgradeMute`）：
1. 打开项目时检测游戏认不认这两种静音（结果在 `P.muteSupport`）。
2. 保存时，只有旧模板才升级，而且只改原来那两个确切位置（`.mp3";a.volume=1;` 和 `va.volume=Math.min(1,a.vol??1)`）；已经支持的游戏一个字不改。以前是全文 `replaceAll('a.volume=1;')`，会误改淡入淡出这类无关代码，而且每次保存都跑。
3. 升级不了（游戏代码改过写法）时，设静音和保存都会提示「游戏里仍会播」，不再静默失效。

改游戏模板时，保留 `[2]?.mute` 和 `.muted?0:` 这两种写法，剪辑台靠它们判断支持不支持。

## 工作数据文件

| 文件 | 谁写 | 内容 |

| `storyboard\shotlist.json` | 剪辑台、人 | `bible` 统一设定；`shots[]` 每个镜头：`shot`、`in_frame`、`location`、`layout`、`desc`、`note`（不发给模型）、`refs`（最多 5 张）、`sketch` |

| `autofix\video_shots.json` | 剪辑台、write_vprompts.py、durations.py | 每条视频：首帧、`prompt`、`describe`（质检标准）、参考图、`mode`（h3 / 海螺）、`duration`、`duration_locked`、`speakers`、`need_mouth`、`novideo`、`prompt_prev` |
| `autofix\out\state.json`、`out_r3\state.json` | autofix.py | 每次生成：第几次、模型、时长、费用、质检结果、AI 改写记录 |
| `autofix\draft\drafts.json` | draft_video.py | 每条草稿出了哪几档 |

| `refs\voice_refs.json` | 剪辑台 | 声音参考：`id`、`name`、`role`、`notes`、`voice_id`、`file`、`clone_status`（空 / pending / ready / error）、`pending_voice_id`、`cloned_from`、`preview_file` |
| `<游戏>\_studio\state.json` | 剪辑台 | `stale`：台词改过、配音要重录的行 |

### review.json 的键

审阅记录都放在一个文件里，靠键名前缀区分。每条一般有 `ok`、`note`，以及审阅当时的 `mtime` 或内容指纹；指纹对不上就算没审过。

| 键 | 是什么的审阅 |
|---|---|
| `<镜头>` | ② 图片 |
| `prompt:<镜头>` | ① 提示词 |
| `ref:<参考图id>` | ⓪ 参考图 |
| `script:<场景>` | 剧本（指纹是场景内容的哈希） |
| `vprompt:<视频>` | ③ 视频提示词（autofix.py 第一次生成前检查它） |
| `final:<视频>` | ④ 成片 |
| `local-video:<文件>` | ④ 加入的本地候选视频（`shot`、`file`） |
| `edit-audit:<id>`、`voice-audit:<id>` | 时间线上的剪辑意见、声音意见（`reviewed` 表示处理过） |

加新的审阅类型时，用新前缀，不要复用已有的。

| 改什么 | 旧的去哪 |
|---|---|

| 参考图重新生成 / 换图 | `refs\_old\` |

## 安全和费用约定

- 密钥只从环境变量读（`GEMINI_API_KEY`、`MINIMAX_API_KEY`、`KLING_API_KEY`），不写进代码和数据文件，不打印。
- 任何会产生费用的调用，界面上先弹 `S.confirm` 写明大概费用，人点确认才执行。一次点击只发起一笔付费调用（自动重拍例外，弹窗里写明最多几倍）。
- 结果不确定的付费请求（网络断、平台 5xx）不自动重试，记成「待核实」，让人去平台核对。
- 渲染进程传来的相对路径都要校验：`core.js` 的 `safeTarget` 只允许写 `img`、`vid`、`vo`、`bgm`、`sfx`、`amb` 这几个素材文件夹，不允许 `..`；`voice-refs-store.js` 的 `audioPath` 只允许 `refs/voices/` 下的音频文件。新加写文件的接口也要走这类校验。
- 仓库是公开的：提交前检查没有密钥、个人路径和不该公开的素材。

## 打包和发布

- `npm start` 开发运行；`npm run dist:win` 打成 `dist\YingyouStudio-<版本>-win-x64.zip`。
