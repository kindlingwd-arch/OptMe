# 影游剪辑台：设计与使用

> 当前版本 v0.6（2026-11-05）。各节标题里的版本号是这个功能第一次加入的版本。
> 代码结构、数据文件和外部脚本的约定见 [架构与数据约定](架构与数据约定.md)；整套制作流程见 [影游制作与优化流程](影游制作流程.md)。

## 目的
互动影游由镜头、配音、音乐和选择组成，用剪辑软件的方式调试比用浏览器调试更直观。剪辑台把游戏剧本（index.html 里的 `const N={...}`）当成剪辑表：每个场景是一条多轨时间线，不满意的画面或声音直接拖进去替换，改完一键导出可以玩的游戏包。

## 设计原则
这几条贯穿所有功能，加新功能时也按它来：

- **越往上游修越便宜。** 审阅按「剧本 → 参考 → 提示词 → 图片 → 草稿 → 成片 → 台词」排，上游改了，下游自动标成「上游改过」等人复查。
- **改动可撤回，原文件不丢。** 替换素材、改分镜表、重新生成参考图、换参考录音，旧文件都先备份（位置见「数据存放」）。
- **花钱的操作先说清楚。** 出图、修图、生成参考图、生成视频、复刻声音、生成试听，都会先弹窗写明大概费用，人点了才执行；不会一次点击隐含多次付费调用。
- **AI 只提议，人定稿。** AI 质检、AI 改写的提示词都要人看过才算数；创作取舍（道具放哪、戴不戴帽子）不交给 AI 决定。
- **状态跟着文件走。** 审过的东西记下当时文件的修改时间或内容指纹；文件换了，自动回到「待审」，不会出现「审的是旧图」。

## 两种工作模式（v0.3，2026-10-30）
按「图片优先」流程，剪辑台分成两种模式，在左上角切换（会记住上次的选择）：

**故事板模式（默认）**：先把剧情和画面定下来，每句台词对应一张静态分镜图。
- 中间默认显示故事板网格，每张卡片是一句台词，显示对应的分镜图、序号、台词、景别和构图。
  - 卡片标签：✓ 通过质检 / ⚠ 需人看 / 人工确认 / 沿用插图 / 自选图 / 沿用场景图（这一句还没有自己的图）。
  - 鼠标停在卡片上可以看到上次质检发现的问题。
  - 单击：选中这一句；双击：切到「预览」从这一句开始玩。
  - 拖图片到卡片上：直接换成这一句的分镜图。
- 顶部是本场的进度条，还有两个按钮：
  - 「给缺图的句子出图」：调用 `storyboard\batch.py`。
  - 「整场检查并自动修」：调用 `storyboard\refine.py`，只处理还没通过的图。
- 右边面板（选中一句台词时）：
  - 分镜画面：可以换图、在文件夹中显示、不用分镜图（改为沿用场景图）。
  - AI 按钮：
    - 框选修图…：打开「审图 · 框选修图」窗口（见下文），框出要改的地方，只改框里。
    - AI 按意见修改…：写一句修改意见，AI 在整张图上改（可能顺手改动别处，局部小问题优先用框选修图）；可以勾选「没通过质检也换进游戏」。
    - AI 检查并自动修。
    - 重画这一张。
    - 不用分镜图。
    - 这张没问题，标记人工确认：质检判没通过、但人看过觉得可以时用（只在没通过的图上出现）。
  - 上次质检发现的问题（附分数）。
  - 分镜要求，这里改的内容直接保存到 `storyboard\shotlist.json`，下次出图和质检都按这个来，每次修改前自动备份到 `storyboard\out\backup\`：
    - 景别；
    - 画面里有谁；
    - 构图（按画面方向写）；
    - 画面描述；
    - 参考图（勾选，最多 5 张）。
  - 分镜表里还没有的台词，点「加进分镜表」或直接点 AI 按钮会自动建一条。
- 时间线的「画面 · 分镜」轨，每句一块，显示分镜图；没有自己的图时显示虚化的场景图，并标注「沿用场景图」。
- 出图任务在右下角的任务栏里显示实时日志，可以停止；最多同时跑 4 个任务。任务完成后，素材、分镜状态和预览会自动刷新。任务开始前如有未保存的修改，会先自动保存。
- 素材检查只查分镜图相关的问题，不提示缺视频。

**视频模式**：画面定下来以后再做动态镜头，包括场景视频、插入镜头、剪辑入点和出点、视频原声。视频的生成和挑选在审阅的「③ 草稿」「④ 成片」里做（v0.6）。

## 审阅总览（v0.4 起，v0.6 扩成 8 页）
审阅是剪辑台的主要工作界面：全屏瀑布流，一条一张卡片，一张张往下刷，全键盘操作。

| 页 | 审什么 | 一张卡片是 | 首次加入 |
|---|---|---|---|
| 剧本 | 剧情结构：走不走得到、线索给没给、台词齐不齐 | 一个场景 | v0.6 |
| ⓪ 参考 | 图片参考图、声音参考（音色） | 一张参考图 / 一条声音 | v0.4（声音 v0.6） |
| ① 提示词 | 出图前，实际发给模型的提示词 | 一个镜头 | v0.4 |
| ② 图片 | 出图后的分镜图 | 一个镜头 | v0.4 |
| ③ 草稿 | 生成视频之前：视频提示词、时长、首尾帧、草稿视频 | 一条视频 | v0.6 |
| ④ 成片 | 最终放进游戏的视频：选哪一版、剪辑点、配音、音效 | 一条视频 | v0.6 |
| ⑤ 台词 | 按角色核对台词和对应配音 | 一句台词 | v0.6 |

- 入口：顶栏「审阅」（上面的数字是各页待审数）；故事板顶部「审阅本场」；菜单「视图 → 审阅分镜图」，快捷键 Ctrl+Shift+A。审阅页左上角切换各页，每页上面有待审数（会记住上次的选择）。
- 顶部切换范围（本场 / 全部场景）和筛选：
  - **待审**：还没审，或审过之后文件又变了。
  - **有问题**：标了有问题、还没解决的。
  - **上游改过**：剧本、提示词或参考图改过，这里还没复查的（只在 ① ～ ④ 出现）。
  - **已通过**：审过、标了没问题的。发现漏了可以在这里找回来，改判有问题或改回待审。
  - **全部**。
  - **Codex 剧本修正**（只在 ② 图片）：按剧本审阅意见由 Codex 重做过的图。
- **跨页联动（v0.6）**：①～⑤ 用同一套「镜头 / 台词」定位。从一页切到另一页时，会停在同一个镜头或同一句台词上；剧本卡片里的「▶ 播放视频」「④ 成片」可以直接跳到对应的视频；右键图片或台词，可以直接写「图片审阅意见」或「视频审阅意见」。
- 每页的批量工具在顶部「🛠 工具 ▾」里（见各页说明）。
- 审阅结果都存在 `storyboard\out\review.json`（不和出图脚本抢着写 state.json），键名约定见架构文档。
- 剪辑台里任何一张图（审阅页、修图对话框、新增参考图、右边面板）都可以**双击放大**，放大后 ← → 翻看同一张卡片里的其他图，Esc 或点空白处关闭。能单击增减的缩略图（参考图、生成时一起参考）单击会稍等约 0.25 秒再生效，所以双击不会误触增减。素材库和时间线保留原来的双击（预览 / 从这句开始播），修图窗口的大图不放大（要在上面画框）。
- 审阅页开着时，按键不会传给后面的剪辑台（不会误删台词）。

### 剧本审阅（v0.6）
一个场景一张卡片，审剧情结构。卡片里列出本场所有台词（可以直接播放对应的视频），以及自动检查结果：
- **走不到**：从开头没有任何选项或密码锁通向这一场 / 这个结局。
- **死路**：不是结局，也没有选项或密码锁通向下一场。
- **选项指错**：指向不存在的场景，或指回本场。
- **线索拿不到**：选项需要的线索，没有任何一场给出；或者走到这里的任何一条路上都拿不到它。
- **线索没用到**：给出了线索，但后面既没有选项用到它，也没有需要推理的密码锁（只提示，不算错）。
- **密码锁**答对 / 答错后去的场景不存在。
- 台词还是空的、没写说话人、没有分镜、分镜没出图。
- 审过记下场景内容的指纹，场景改了就回到「待审」，卡片上标「剧本改过，下游 N 处要复查」，点它直接列出本场相关的提示词和图片，顺着往下复查。

### ⓪ 参考：图片参考图
- 参考图登记表：`refs\refs.json`，每张参考图记名称、类型（人物 / 道具 / 场景）、生成描述、关键词（提示词里出现这些词时应该附上它）、生成时一起参考的其他参考图。第一次打开时按 `refs\` 里已有的图自动建登记，描述取自原来的 `ref_prompts\<id>.txt`。
- 每张卡片：左边大图（双击放大）和「生成时一起参考」；右边是名称、待审状态、几个镜头在用、「统一设定里的写法」（对照看图对不对）、「提示词里提到它却没附上的镜头」（可以一键全部附上），以及可直接修改的名称、类型、关键词、描述。
- 操作：A 参考图没问题；R 按描述重新生成（调用 `storyboard\ref_tool.py`，Gemini 出图，约 $0.14）；换成本地图片；看用到它的镜头（跳到提示词审阅）。重新生成或换图后，原图挪到 `refs\_old\`，不会丢；参考图换了就自动回到「待审」；用到它的镜头要重画才会用上新图。
- 新增参考图：审阅页顶部「＋ 新增参考图」，或提示词卡片参考图一栏最后的「＋ 新增」，或自动检查里的「＋ 新增参考图」按钮（名称、文件名、关键词、描述按常见道具预填：第四套人民币、BP机、财产保险单、白信封、车载收音机、警车、手电筒、箱子里的金货）。可以 AI 生成，也可以导入本地图片；从提示词卡片打开时可以同时附到这个镜头。
- 2026-10-31 用真实的 40 条跑：参考图库里没有、但提示词提到了的有 8 种（收音机 3 个镜头、钞票 1、保险单 4、BP机 2、警车 1、手电 5、信封 2、金光 1）；已有参考图但没附上的有 5 张（客运站 2、车内 1、黑皮箱 2、林间公路 1、出租车 4）。
- 发现：统一设定里写的是「红色夏利出租车」，没写两厢；原来生成出租车参考图的描述里写的是 hatchback（两厢）。建议统一设定补上「五门两厢（掀背）」。

### ⓪ 参考：声音音色（v0.6）
⓪ 参考页顶部切换「图片参考 / 声音音色」。声音参考和出图参考分开管理，不会混进出图的参考图里。

- 登记表：`refs\voice_refs.json`；参考录音和试听存在 `refs\voices\`。每次改登记表前，旧登记表备份到 `refs\voices\_old\`。
- 每条声音参考记：音色名称、对应角色（从剧本里的说话人选）、声音特点与备注、MiniMax 音色 ID、参考录音。
- 流程：
  1. 「＋ 添加声音参考」，填名称和角色，保存后选参考录音。
  2. 选录音时打开项目音频选择器：默认列出「分离音频」（从视频里分出来的原声，`sfx/va_*`），也可以切到「全部本地音频」或从电脑导入。同一个人的几段短录音可以勾选后**合并**成一段作为参考（在本地合并成 WAV，不上传）。
  3. 「生成音色」：把参考录音上传到 MiniMax 复刻音色。录音要求 10 秒～5 分钟、MP3 / M4A / WAV、不超过 20 MB。点之前会弹窗确认，并提醒「请使用你有权使用的声音」。复刻本身不附带试听，避免一次点击产生多笔费用。
  4. 「生成试听…」：写一句 1～300 字的试听台词，用这个音色合成（MiniMax `speech-2.8-hd`）。
- 防重复扣费：
  - 同一条声音正在处理时，再点会被拒绝。
  - 已经有音色 ID 的，不能再「生成音色」；要重新复刻就另建一条。
  - 复刻请求发出去但结果不确定（网络断、平台 5xx），状态记成「待核实」，并记下准备用的音色 ID；这时不能自动重新提交，要先去 MiniMax 后台核对。
  - 生成期间参考录音被换了，结果不会自动写进登记表，而是提示音色 ID 让人手动核对。
- 已有复刻音色的，可以直接在「MiniMax 音色 ID」里填写，不用重新复刻；改了音色 ID，旧试听会清掉。
- 「移除」只删登记，原录音和历史备份保留。
- 需要环境变量 `MINIMAX_API_KEY`（或 `KLING_API_KEY`）。余额不足时会提示「账户余额不足，音色尚未生成」。

### ① 提示词审阅
- 每张卡片：左边是现在的成图、构图图、俯视位置图和参考图（参考图单击增减，最多 5 张；任何图双击放大，放大后 ← → 翻看本卡的其他图，Esc 关闭）；右边是台词、自动检查结果、可直接修改的分镜字段（景别、场景、画面里、构图、画面描述、备注），改完点别处自动保存到 `shotlist.json`（自动备份）。
- 「实际发给模型的完整提示词」可以展开看，拼法和 `storyboard\batch.py` 的 `prompt()` 逐字一致（两边各有注释提醒同步修改）。
- 自动检查（出图前就能挑出来的常见问题，代码在 `renderer\app.js` 的 `lintShot`）：
  - 构图或画面描述里出现的人，「画面里」没写（机位、视线方向里提到的不算；只露手、背影这类局部单独提醒）；
  - 从后座往前拍，「画面里」却没有司机；
  - 左舵方向写反（从车里往前看司机应在画面左，从车头前方往里看应在右）；
  - 机位朝后，但统一设定里有挡风玻璃下的红穗子；
  - 写了「后备箱」（参考图的夏利是五门两厢车）；
  - 「远离 / 那边 / 旁边」这类容易理解偏的方向词；
  - 要求画面上的字清楚，和「画面里不要任何文字」冲突；
  - 台词说指甲，提示词却写戴着手套；
  - 备注里像是有画面要求（备注不会发给模型）；
  - 参考图超过 5 张，或缺了画面里的角色；
  - 提到了登记表里某张参考图的关键词却没附上（旁边有「附上」按钮）；提到了参考图库里根本没有的东西（旁边有「＋ 新增参考图」按钮）。「没有警车」「看不到后视镜」这类否定说法不算提到。
  - 2026-10-31 用真实的 40 条跑：6 处矛盾、24 条提醒，和人工审的结论一致。
- **衔接检查（v0.6）**：工具里「检查衔接」，把同一场相邻镜头放在一起，查连着播时接不接得上（视线方位、人物位置、越轴、地点背景、光线、衣服道具）。调用 `storyboard\continuity.py`，结果存在 `storyboard\out\continuity.json`；检查之后又改过的会标「需要重新检查衔接」。① 提示词和 ② 图片各查一遍。
- **手绘构图（v0.6）**：难镜头可以自己画构图图或俯视位置图，选「用我手绘的」直接用，或「用 AI 整理的」让 `sketch_ai.py` 整理成干净的构图图。
- 操作：A 提示词没问题（自动跳下一条）；R 按这条出图 / 重画；↑ ↓ 翻页。提示词、参考图或构图图任何一样改了，就自动回到「待审」。
- 出图前提醒：任何地方点出图 / 重画（故事板、右边面板、审阅页），如果有还没审过的提示词，会先弹窗提醒，并标出其中自动检查发现矛盾的镜头；可以选「先去审提示词」「照样出图」或取消。

### ② 图片审阅
- 每张卡片：左边大图，右边是场景和第几句、台词、AI 质检结果、分镜要求、AI 质检发现的问题、审阅意见、其他候选。
- 操作（键盘可以不碰鼠标）：
  - ↑ ↓（或 K / J）：上一张 / 下一张；
  - A 通过：记为人工通过，自动跳到下一张；
  - X 有问题：写一句哪里不对，「只记下」或「记下并让 AI 按意见修改」（调用 refine.py 的人工意见模式）；
  - E 修图：打开框选修图窗口；
  - R 重画：按分镜表整张重画（batch.py）；
  - 点「其他候选」的缩略图可以放大看之前几次出的图，满意就「用这张」换进游戏；
  - 「本地替换」：用电脑里的一张图换掉当前图（`fix_box.py local`）；
  - 双击大图全屏放大；
  - Esc 关闭。
- 「待审」包括 AI 质检通过的图，人都要过一遍；在修图窗口里采用或标记人工确认过的，算已通过。
- 每条记下审阅时游戏里那张图的修改时间，图被换掉（重画、修图、拖图替换）就自动回到「待审」。

### ③ 草稿（v0.6）
用分镜图生成视频之前的最后一道关：先用免费或很便宜的草稿把动作、时长、衔接看对，再花钱生成正式视频。一条视频一张卡片。

- 卡片内容：首帧（定稿的分镜图）、视频提示词、质检标准、时长、参考图、尾帧、草稿视频。
- 视频提示词：
  - 「AI 写视频提示词」：Gemini 看首帧图和剧本，重写这一条的视频提示词和质检标准（约 $0.01）；原来的存进 `prompt_prev`。
  - 「✎ AI 重写全部视频提示词」（工具）：一次重写所有视频（标了「不做视频」的除外），先出草稿和图片版预览，在「📋 草稿预览」里勾选后才写进视频分镜表。
  - 剪辑台按剧本自动补的视频条目，提示词是从环境 / 画面描述抄来的，会单独标出来。
  - 第一次正式生成前，提示词要人确认过；没审过（或审过又改了）会弹窗提醒。
- 时长：「⏱ 按剧本算时长」（工具，`durations.py`）。场景视频播到切走为止（字幕卡、台词配音的长度），插入镜头按动作要多久，再对到模型支持的时长（海螺 6 / 10 秒，H3 4～10 秒）。手改过的标「手改」，重算时不动。
- 草稿的几种做法（都调用 `autofix\draft_video.py`，输出到 `<游戏文件夹>\vid_draft\`，和正式视频同样的相对路径；记录在 `autofix\draft\drafts.json`）：
  - **代码草稿**（免费，每条几秒）：首帧图 + 代码做镜头运动（按提示词里的推近 / 拉远 / 摇），顶部有动作提示条按时间依次亮起；有尾帧就在后半段淡入，有手绘动作就画出轨迹，台词页带配音。时长和正式视频一样。「🎞 全部出草稿（免费）」一次出全部；然后预览里选「草稿」（游戏的 `?draft=1` 模式），在游戏里把整个剧情过一遍。
  - **AI 画尾帧 + 草稿**（约 $0.14 一张）：Gemini 按提示词画「这段视频最后一刻」的画面；满意的话「用作正式尾帧」，正式生成就走首尾帧模式，终点锁得更准；也可以「不用尾帧了」。
  - **2.5D 预演**（免费，要装 Blender）：首帧估深度变成立体场景，人和车抠成卡片在地上走，按参数控制镜头、光照、雪；用 Blender 渲染。
  - **本地模型草稿**（不花 API 钱，要 NVIDIA 显卡）：用本地开源视频模型 LTX-Video 出一段会动的草稿。第一次要运行 `autofix\install_local_video.bat` 并下载约 20 GB 的模型。先用「🖥 检查显卡」看这台电脑能不能跑（显卡、显存、PyTorch）。
- **手绘动作（v0.6）**：在首帧上用鼠标画每个人 / 物的运动路线（录下位置和时间，存 `storyboard\sketch\<镜头>_motion.json`）。`autofix\motion_sketch.py` 先用代码把抖动的轨迹修顺（坐标和时间照人画的，不让 AI 改），再让 Gemini 认出每条路线是谁、写一句动作和视频提示词、指出不合理的地方（比如起点不在那个人身上），最后生成参考视频。结果写进 `autofix\test_motion\<镜头>\motion.json`，代码草稿也会画出这条路线。

### ④ 成片（v0.6）
最终放进游戏的视频：选哪一版、剪辑点、配音、音效 / 原声，连声音一起看。一条视频一张卡片。

- **生成视频**：交给视频模型生成（`autofix\autofix.py`），生成后 Gemini 质检打分；质检不通过会用 AI 改写的提示词（先过滤敏感词）自动重拍，每次 AI 改写都记进记录，剪辑台里能看到。需要 `MINIMAX_API_KEY` 和 `GEMINI_API_KEY`，每条几分钟。
  - 第一次生成前，视频提示词必须在 ③ 草稿里人审过（记的是提示词指纹，改过就要重审）；之后的自动重拍放行（2026-11-01 定的「方案 C」）。
  - 预算上限：环境变量 `AUTOFIX_BUDGET`（元，默认 20），花到上限就停。
  - 质检不通过最多再拍 1 次（共 2 次生成，`autofix.py` 的 `MAX_RETRY = 1`），所以最多约 2 倍费用。
  - ⚠ 网络出错时会自动重新提交（最多 6 次，见架构文档「已知问题」），有重复扣费的风险。
  - 生成前弹窗选模型，并按时长显示费用：

  | 模型 | 价格 | 说明 |
  |---|---|---|
  | 海螺 2.3 · 768P | 6 秒 ¥2.0 / 10 秒 ¥4.0 | 现在大部分镜头用的；只有 6 / 10 秒 |
  | 海螺 2.3 Fast · 768P | 6 秒 ¥1.35 / 10 秒 ¥2.25 | 便宜三成，速度快，画质略低 |
  | H3 · 768P | ¥0.50 / 秒 | 4～10 秒按需要的长度生成；首帧锁构图（帧模式） |
  | H3-Lite · 768P | ¥0.26 / 秒 | H3 的便宜版，先测画质 |
  | 海螺 02 · 512P | 6 秒 ¥0.6 / 10 秒 ¥1.0 | 低清草稿，看动作和嘴型走向，不进游戏 |
  | H3-Lite · 480P | ¥0.16 / 秒 | 低清草稿，看动作和嘴型走向，不进游戏 |

  价格写在 `renderer\app.js` 的 `ENGINES` 里，平台调价时要同步改；实际以平台账单为准。上次选的模型会记住。
  - 不勾「多生成一版」（`--again`）：不通过时自动重拍 1 次，最多约 2 倍费用；通过就自动换进游戏。
  - 勾「多生成一版」（`--more`，已经生成过的镜头默认勾上）：保留以前的版本，只生成一次，不自动换进游戏，到候选里和别的版本对比后再选用。
- **候选**：卡片里列出所有版本——每次生成（第几次、模型、时长、费用）、本地候选、本地备份——可以逐个试听，点「用作成片」换进游戏。
- **本地视频（v0.6）**：
  - 「更换本地视频…」或直接把一个 MP4 拖到卡片上：替换当前成片。原片自动备份到 `_studio\backup\`，配音和剪辑设置保留，换完回到「待审」。
  - 「加入本地候选…」：只导入到 `_studio\inbox\`，加进候选列表，不替换成片；试听满意再「用作成片」。
  - 只收 MP4，其他格式先转码。
- **剪辑编辑器**：大画面 + 时间条（拖入点 / 出点）+ 配音轨 + 音效轨，连声音一起试听，改完保存进游戏。视频本身有声音时，可以把原声分离出来单独调音量或静音。
- **按需加载**：成片卡片默认不加载视频，点「▶ 播放视频」才加载；同时只保留一个在播的视频，翻走就释放，避免几十条视频同时占内存。播放失败会显示「播放失败，点击重试」。

### ⑤ 台词（v0.6）
按角色查看台词、试听对应配音。一句台词一张卡片。

- 台词和配音的对应关系按剧本里的 `VOT` 映射（台词文字 → `vo/<key>.mp3`）找，不按分镜编号猜文件名。
- 每句的状态：**齐全**（有配音）/ **缺失**（没有配音文件）/ **改字待更新**（台词改过，配音还是旧的）。顶部进度条显示「台词 N 句 · 配音齐全 · 缺失 · 改字待更新」。
- 可以按角色、状态、文字筛选；能播放这句对应的视频片段（带配音）。
- 用 ⓪ 声音音色里复刻好的音色，可以给这句**生成配音**（MiniMax，单句最多 300 字，点之前确认费用）。生成的音频存成新文件 `vo/ai_<随机编号>.mp3`，旧配音文件不删；台词绑定到新文件，按 Ctrl+S 才保存。剧本里相同的台词共用一个配音，会一起更新，弹窗里会写明有几句。不满意可以 Ctrl+Z 撤回绑定。
- 可以给这一句写审阅意见（配音、音效、原声）。

## 时间线审阅意见（v0.6）
在时间线的音频块上右键，可以在指定位置写一条意见（剪辑意见或声音意见），记下场景、片段时间段和右键的位置。时间线顶部的审阅条列出还没处理的意见，逐条确认处理完。意见存在 `review.json` 的 `edit-audit:` / `voice-audit:` 键下。

## 审图 · 框选修图（v0.4，2026-10-31）
细节问题（钞票颜色、车顶灯上的字、道具样式）用「改提示词、整张重画」效率低，而且会把画对的地方改坏。框选修图只改框出来的地方。构图问题（谁在哪、朝哪、机位）仍然用构图草图解决。
- 入口（三个，都在故事板模式下）：
  - 鼠标停在故事板卡片上，右上角出现「✎ 修图」；
  - 选中一句台词，右边面板顶部的「✎ 审图 · 框选修图…」；
  - 菜单「编辑 → 审图 · 框选修图」，快捷键 Ctrl+Shift+F。
- 更新程序文件后要完全关掉剪辑台再打开（或菜单「视图 → 重新加载界面」），否则还是旧界面。
- 窗口左边是这一句当前的分镜图（游戏里的 16:9 画面），右边是质检发现的问题、分镜要求和修改栏。
- 用法：
  1. 在图上按住鼠标拖出方框（R），或沿着轮廓画一圈（套索，v0.6），右边写一句怎么改；可以框好几处。
  2. 选修改方式（见下），点「修改框里的内容」，约 30～60 秒（右下角任务栏有日志）。
  3. 用「修改前 / 修改后」切换对比（「只改样子」时还有「差异」，标出被 AI 改动的像素），然后三选一：采用这张、换进游戏；在这张基础上继续改；不要、回到修改前。
  4. 不需要改、只是人看过觉得可以：点「这张没问题，标记人工确认」。
- 两种修改方式（按会不会改变形状来选）：
  - **只改样子，形状不变**（patch）：换颜色、盖掉字、换道具花纹。只把框附近一块裁下来发给 AI（红框画在框外侧），改完只取回框里的像素，边缘羽化贴回原图，框外一个像素不变（用故意捣乱的假 AI 测过：框外改变 0 像素）。每个框调用一次 AI。
  - **要加东西或改形状**（whole）：箱子里加金子、给人戴上帽子。新东西可能长出框外、要有影子和反光，硬贴回会有接缝，所以整张交给 AI：发两张图——干净原图（让 AI 改）和画了编号红框的位置图（只指位置），用 AI 改完的整张图。因为要改的那张图上本来就没有红框，结果里不会残留红线。所有框一次调用。改完会报告「框外变化」大小（很小 / 有一些 / 较大），并检查有没有疑似残留红线，供对比时参考。
- 背后调用 `storyboard\fix_box.py`：
  - `python fix_box.py edit <镜头> <base64(JSON)>`：JSON 里 `mode` 是 `patch` 或 `whole`，框用 0～1 的比例坐标，相对 16:9 画面；
  - `python fix_box.py accept <镜头> <结果文件>`：换进游戏，分镜状态记为「人工确认」（manual）；
  - `python fix_box.py approve <镜头>`：不改图，只标记人工确认；
  - `python fix_box.py local <镜头> <图片>`：用本地图片替换（v0.6）；
  - 不带参数运行（或双击 `storyboard\run_fix_box.bat`）是独立的网页版，功能相同。
- 修改结果、每次发给 AI 的局部图（patch）和位置图（whole）都在 `storyboard\out\fix\`；采用前的原图保留在 `storyboard\out\` 里。
- 每次调用约 $0.14，计入 `storyboard\out\batch\state.json` 的累计费用。需要 `GEMINI_API_KEY` 和代理。
- 状态为「人工确认」的镜头，`run_batch.bat` 重跑时会跳过（2026-10-31 起），`refine.py` 默认也不处理。

## 数据约定
- 每句的分镜图存放在 `<游戏文件夹>\img\l\<场景>_<两位行号>.jpg`。
- 剧本里的写法是 `["你","台词",{"img":"l/ride_00"}]`；游戏里还有一份 `LIMG` 登记表，作为兼容。台词的第三项还可以带 `mute`（这句静音，v0.6）。
- 静音要游戏的 index.html 支持（新模板自带）。剪辑台打开项目时会检测；游戏不支持时，设静音和保存时都会提示「游戏里仍会播」，不会悄悄失效。
- 剪辑台打开项目时，会把已登记的图，或者分镜表里有、图片文件也存在的图，钉到对应的台词上。这样以后插入或移动台词，图也不会对错。
- 分镜工作区固定在游戏文件夹旁边的 `storyboard\`，视频工作区在 `autofix\`，参考图和声音参考在 `refs\`。完整的文件清单见 [架构与数据约定](架构与数据约定.md)。
- Python：依次找环境变量 `YINGYOU_PYTHON`、`%USERPROFILE%\anaconda3\python.exe`、`python`。

### 需要的密钥

|---|---|
| `GEMINI_API_KEY` | 出图、质检、修图、参考图、视频提示词改写、视频质检、衔接检查。受限地区需要代理 |
