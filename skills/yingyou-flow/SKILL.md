# 影游制作与优化流程

用户说「按流程过一遍 xx」「优化这一场」「审一下提示词 / 参考图 / 图片」「这张图有问题帮我修」「把这个问题归类」时，按这里的步骤做。团队看的完整说明在仓库的 `docs/影游制作流程.md`，剪辑台每一页怎么用在 `docs/影游剪辑台_设计与使用.md`，文件和数据结构在 `docs/架构与数据约定.md`（仓库在 `影游剪辑台\resources\app\`）；出图质检经验在 `storyboard\QC经验.md`，视频在 `autofix\使用说明.md`。先读相关的那份，再动手。

## 核心原则

- **越往上游修越便宜**：参考图 → 提示词 → 构图 → 出图 → 修图 → 视频。发现问题先归类，回到它所属的那一步修，不要在下游反复重画碰运气。
- **每一步有一道关**，过了关才进下一步。图片版没定稿，不做视频。
- **人工发现的新问题要变成规则**，让上游的自动检查以后能拦住（见「反馈闭环」）。
- 花钱的操作（出图、修图、生成参考图、视频、声音复刻、配音）先说清楚数量和大概费用，等用户同意再做；出图约 $0.14/张，修图约 $0.14/次，AI 写视频提示词约 $0.01/条，视频按模型约 ¥1.3～5/条（价格表在剪辑台 `renderer\app.js` 的 `ENGINES`），声音复刻和配音按 MiniMax 计费。
- **结果不确定的付费请求不要重试**（网络断、平台报 5xx、声音复刻状态「待核实」）：先让用户去平台核对，避免重复扣费。
- 复刻声音只用用户有权使用的录音；不确定就问。

## 文件和工具在哪（项目根目录 `Desktop\moban_art\`）

| 东西 | 位置 |
|---|---|
| 游戏 | `moban_game\index.html`（剧本 `const N=`，逐句分镜图 `img\l\<场景>_<两位行号>.jpg`） |
| 分镜表 + 统一设定 | `storyboard\shotlist.json`（`bible` 是统一设定；每条镜头：shot、in_frame、location、layout、desc、note、refs、sketch） |
| 出图记录 | `storyboard\out\batch\state.json`（每个镜头的 status：pass / best / manual / reuse，tries、refine、final；累计费用 spent） |
| 人工审阅结果 | `storyboard\out\review.json`（`<镜头>`=图片，`prompt:<镜头>`=提示词，`ref:<参考图id>`=参考图，`script:<场景>`=剧本，`vprompt:<视频>`=视频提示词，`final:<视频>`=成片；mtime 或指纹不对就算没审过。完整键名见 `docs/架构与数据约定.md`） |
| 参考图 | `refs\<id>.png`，登记表 `refs\refs.json`（名称、类型、描述、关键词、生成时一起参考的 inputs）；旧图在 `refs\_old\` |
| 声音参考 | 登记表 `refs\voice_refs.json`（角色、MiniMax 音色 ID、复刻状态），录音和试听在 `refs\voices\` |
| 构图图 | `storyboard\sketch\<镜头>.png`、`<镜头>_map.png`（俯视位置图） |
| 视频分镜表 | `autofix\video_shots.json`（首帧、视频提示词、质检标准、时长、生成方式）；生成记录 `autofix\out\state.json` |
| 脚本 | `storyboard\batch.py`（出图+质检，最多 3 次）、`refine.py`（检查→局部修改/重画；带一句意见时按意见改）、`fix_box.py`（框选修图）、`ref_tool.py`（生成参考图）、`continuity.py`（相邻镜头衔接）、`gen_images.py`（Gemini 调用）；视频在 `autofix\`（`write_vprompts.py`、`durations.py`、`draft_video.py`、`autofix.py`）和 `qc\` |
| 剪辑台 | `影游剪辑台\YingyouStudio.exe`（程序文件 `resources\app\`，也是 GitHub 仓库 `kindlingwd-arch/OptMe`）：故事板、审阅（剧本 / ⓪ 参考 / ① 提示词 / ② 图片 / ③ 草稿 / ④ 成片 / ⑤ 台词）、框选修图 |

脚本要用用户电脑上的 `GEMINI_API_KEY` 和代理。如果你只能通过文件桥接访问用户电脑、执行不了 Windows 程序，就准备好文件，告诉用户双击哪个 `.bat` 或在剪辑台里点哪个按钮，跑完再来看结果。

## 流程

### ⓪ 设定和参考图
1. 读 `bible` 和 `refs\refs.json`，看图（参考图要真的打开看）。
2. 对照统一设定挑问题：车型（夏利是五门两厢）、人物长相服装、道具年代。
3. 扫一遍分镜表，找提示词里提到但参考图库里没有的东西（钞票、BP机、保险单、信封、收音机、警车、手电、金货……），列出建议新增的参考图，描述要写明年代和样子、不要文字。
4. 过关：每张参考图人工确认；提示词提到的东西都有参考图。

### ① 分镜表和提示词
1. 按出图脚本的拼法看「实际发给模型的提示词」（`batch.py` 的 `prompt()`；剪辑台的提示词审阅显示同样内容）。
2. 逐条对照台词、统一设定和参考图检查，重点查：
   - 构图 / 描述里出现的人，「画面里」有没有写（只露手、背影也要写明）；
   - 从后座往前拍要写司机；机位朝后不要出现后视镜红穗子；
   - 左舵方向：从车里往前看司机在画面左，从车头前方往里看在右；
   - 方向词别用「远离、那边、旁边」，写画面左右、前排后排；
   - 关键要求不能只写在 `note`（备注不会发给模型）；
   - 和台词矛盾的地方（例：台词说看指甲，提示词却写戴手套）；
   - 参考图最多 5 张，该附的有没有附。
3. 改 `shotlist.json` 前先备份到 `storyboard\out\backup\`；涉及创作取舍的（道具放哪、人物戴不戴帽子）先问用户，不替他们决定。
4. 过关：没有矛盾，每条人工确认。

### ② 构图（难镜头）
车内、左右关系、多人、机位朝后的镜头，先出构图图（画面里不要文字）和俯视位置图（可以有标注），登记到 `sketch` 字段。构图图越明确越好：小而模糊的人物会被模型挪位置。

### ③ 出图 + AI 质检 + 自动修
- 缺图的：`python batch.py <镜头…>`（或剪辑台「给缺图的句子出图」）。
- 没通过的：`python refine.py`（不带参数只处理没通过的；**不要把已经通过的镜头传给 refine.py**，更严的复检会把好图换掉）。
- 出图前确认提示词审过。

### ④ 图片审阅
每张图都要人看过（AI 通过的也要看）。处理方式：
- 细节、形状不变（颜色、文字、小道具）：框选修图「只改样子」（框外像素不变）。
- 要加东西、改形状：框选修图「要加东西或改形状」（整张交给 AI，看「框外变化」报告）。
- 结构问题（多人、座位、机位）：不要修图，回到 ① 或 ② 改了再重画。
- 之前某次候选更好：直接换成那张。

### ⑤ 图片版试玩
先看剪辑台「审阅 → 剧本」的自动检查（走不到、死路、线索拿不到），再整局玩一遍（剪辑台预览、AI 试玩、真人试玩），记录剧情、线索、节奏、画面衔接问题，按「反馈闭环」归类。

### ⑥～⑨ 视频、声音、导出（只对定稿的部分做）
1. **草稿**（剪辑台「③ 草稿」）：AI 写视频提示词（`write_vprompts.py --draft`，先出草稿，人勾选后才 `--apply`）→ 按剧本算时长（`durations.py`）→ 代码草稿（`draft_video.py`，免费）→ 预览选「草稿」整局过一遍。
2. **视频提示词人审**：第一次正式生成前必须在剪辑台审过（`vprompt:` 记录），不要用 `--force` 跳过。
3. **生成**（剪辑台「④ 成片」或 `autofix.py`）：用定稿图当首帧，AI 质检不通过自动重拍；先报模型和费用。
4. 不张嘴的做口型同步（`autofix\lipsync.py`）。
5. **声音**：「⓪ 参考 → 声音音色」复刻角色音色，「⑤ 台词」查缺失和改字待更新的配音、补配音；声音质检。
6. 剪辑台素材检查 → 导出。

## 反馈闭环：问题归类

| 现象 | 归到 | 修法 |
|---|---|---|
| 车型、长相、道具样子错，而且多张图都错 | ⓪ | 改参考图 / 补统一设定 |
| 画出了参考图里没有的东西，样子或年代不对 | ⓪ | 新增参考图并附到镜头 |
| 多一个人、座位错、和台词不符、重画几次都同样错 | ① | 改分镜字段 |
| 左右反、机位方向错、车头朝向错 | ② | 改构图图 |
| 局部细节 | ④ | 框选修图 |
| 剧情、线索、节奏 | ⑤ | 改剧本，再回 ① |
| 视频不张嘴 | ⑦ | 口型同步 |

每发现一种新问题：能从文字看出的，加进剪辑台提示词检查（`resources\app\renderer\app.js` 的 `lintShot`）；只能看图看出的，加进出图质检（`batch.py` 的 `qc()` 提示）和视频质检（`qc\specs.json`）；所有图都该遵守的，加进 `bible`。然后更新 `docs/影游制作流程.md` 的「踩坑规则表」。
