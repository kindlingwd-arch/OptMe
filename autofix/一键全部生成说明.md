# 一键补齐全部视频

双击项目 autofix/run_all_videos.bat 即可启动，不需要逐条人工审核，也没有默认两个镜头的数量限制。

流程：扫描全部分镜 → 保留已有非空成片、排除“不做视频” → Gemini 对照首帧、参考图、剧本和设定审核提示词 → 通过后调用原 autofix.py → Gemini 检查成片 → 不通过自动改写并重拍，最多再拍一次（每条共两次生成） → 原流程备份并安装通过的成片。提示词未通过或接口失败会记录后继续下一个镜头。

这次授权以 Gemini 自动检查替代人审，使用原生成器的 --force 参数，但只在 Gemini 明确返回通过后才执行。不伪造或修改剪辑台的人审记录，也不改写现有 video_shots.json。该全量入口独立于之前的人审批量入口。

默认自动估算全部待生成镜头每条最多两次生成的预算，不再按 20 元停止；预算按项目已有 cost 或模型估价计算，并非服务端硬限额，Gemini 检查另行计费。可在终端指定预算：

```powershell
.\autofix\run_all_videos.bat --budget 300
```

已有视频默认只按非空文件判断并保留，不代表本次经过 Gemini 复核。如果要把已有视频也全部重新生成：

```powershell
.\autofix\run_all_videos.bat --regenerate
```

默认统一使用项目配置的 H3 · 768P（--engine h3），无需额外指定。若需其他模型，可添加 --engine hailuo 或项目已有其他模型名。自动预算也按 H3 对应时长和估价计算。

只预览、不调用模型：

```powershell
& "$env:USERPROFILE\anaconda3\python.exe" .\autofix\run_all_videos.py
```

视频密钥优先读取 KLING_API_KEY，也兼容 MINIMAX_API_KEY；检查使用 GEMINI_API_KEY。GEMINI_MODEL 可覆盖项目默认模型。脚本不保存密钥，只在当前进程内适配原生成器的变量名，不修改系统环境变量。模型及接口仍沿用原 autofix.py（api.minimaxi.com），变量名不会自动切换为可灵官方接口。

进度直接显示在窗口，日志与汇总保存在 autofix/out。all_videos_report.json 区分 passed（通过）、prompt_rejected（提示词未通过）、failed/error（生成失败）、needs_lipsync（已安装，但仍需处理口型）。未通过条目不会被标记为全部完成。生成费用记录仍在原 state.json。历史汇总会自动备份。

任务锁会自动检测进程：确认原进程已退出时回收遗留锁；原进程仍在运行或无法确认时拒绝重复启动。若服务返回 insufficient balance / 余额不足，则停止后续提交，并在汇总中保留尚未处理的 pending 镜头，处理余额后重新启动即可。

请避免与剪辑台或其他生成入口同时运行。关闭窗口不会取消已经提交到平台的远端任务；强制结束后再运行可能重复计费。正常结束后再次启动会跳过已安装的非空成片；needs_lipsync 也可能已有安装文件，需要查看汇总后决定是否 --regenerate。远端服务异常或连续两次不通过时不能保证每条成片都成功，但脚本会遍历全部任务并汇总失败项。

验证范围：使用本地测试和真实项目预览验证，交付时未启动付费生成。
