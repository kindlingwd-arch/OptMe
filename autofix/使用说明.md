# 批量生成视频

将 batch_generate.py、run_video_batch.bat 放到项目 autofix 文件夹。它们读取当前 video_shots.json，调用原 autofix.py，沿用模型接口、生成后质检、最多一次重拍、成片安装和旧文件备份。

双击 autofix/run_video_batch.bat：只预检，不调用模型。检查全表，不受旧入口 auto=true 名单限制。不会重写图片、提示词或审核记录。

在项目目录打开终端：

```powershell
# 检查所有分镜
.\autofix\run_video_batch.bat
# 正式生成：选可生成的前两个镜头，本次新增生成预算约 20 元
.\autofix\run_video_batch.bat --run --limit 2 --budget 20
# 指定镜头；沿用各镜头原有模型配置
.\autofix\run_video_batch.bat start s_knock --run --budget 20
# 指定项目已有模型配置
.\autofix\run_video_batch.bat start --engine hailuo --run --budget 10
# 重新生成指定镜头；通过质检后由原程序备份和替换
.\autofix\run_video_batch.bat start --regenerate --run --budget 10
```

默认跳过非空已有成片及“不做视频”条目；需要重拍旧片时明确指定镜头并加 --regenerate。现有成片不按时间戳自动判定过期。未安装且上次需要人工处理的镜头不会默认重试。

首帧使用 autofix 下的 key 优先，否则 moban_game 下的 keyframe；尾帧、中间帧和配置过的参考图缺失时先阻止该镜头，避免原流程静默丢参考。每次正式调用前都核对当前提示词指纹，待审镜头在剪辑台“审阅 → ③ 视频提示词”确认后再运行。不提供跳过审核开关。placeholder 只是历史占位标记，已审核的当前提示词仍可生成。

视频密钥优先读取 KLING_API_KEY，兼容 MINIMAX_API_KEY；质检读取 GEMINI_API_KEY。密钥不写进脚本。支持模型：hailuo、hailuo_fast、hailuo02_512、h3、h3_lite、h3_lite480，参数和估价均由原 autofix.py 处理，远端可用性需实际调用验证。这里只适配密钥变量名，接口仍沿用原 api.minimaxi.com，不自动切换为可灵官方接口。

预算是项目内部的生成费用估算，不是服务端硬限额，也不含 Gemini 质检费用。新入口将“历史累计估算 + 本次预算”传给原程序。每个镜头可能生成最多两版。预算不足会停止，稍后再次运行可以继续处理未完成镜头。

日志：autofix/out/batch_日期_时间.log；状态及质检报告仍在 autofix/out/state.json、autofix/out/autofix.html；成片按 video_shots.json 的 video 路径装入 moban_game。日志在任务结束后查看，也可运行中用 Get-Content -Wait 查看。

请避免与剪辑台的生成任务同时运行。批量入口间有锁；如强制终止后遗留 batch_generate.lock，确认无任务运行后再删除。原生成器没有远端任务断点恢复能力，提交后强制终止可能导致任务继续计费，重跑可能重复提交。

预检：默认不调用模型；可加 --report 文件路径导出 JSON 清单。退出码：0 为预检成功或全部选中任务完成，1 为生成部分未完成，2 为配置错误或执行时无可生成任务。
